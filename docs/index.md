# Don't learn tech. Build it.

<hr class="h-rule">

Nine months from your first commit to a portfolio you can put in front of an
employer. You'll learn to work with data, train models, and build with AI —
in that order, because each one rests on the last.

[Start here](01-tools/index.md){ .h-button }

</div>

## What you'll become

The programme is built around three roles the industry actually hires for. You
work through them in sequence, and each one leaves you with skills that stand
on their own.

<div class="grid cards" markdown>

-   :material-chart-box-outline: **Data Analyst**

    ---

    Get data out of messy sources and make it say something useful. Python,
    pandas, SQL, visualisation, and the statistics behind an honest conclusion.

-   :material-chart-timeline-variant: **Machine Learning Engineer**

    ---

    Move from describing data to predicting from it. Core algorithms, the full
    training lifecycle, neural networks, and computer vision.

-   :material-robot-outline: **AI Engineer**

    ---

    Build with language models rather than around them. NLP, LLMs, generative
    AI, and getting a working system in front of real users.

</div>

Each stage assumes the one above it. Skipping ahead usually costs more time

## How to work through it

!!! tip "Read less, build more"

    Every tutorial ends with something running on your machine. If you finish a
    page and nothing runs, you skipped the part that mattered.

- Type the code out rather than copying it. The mistakes you make are the lesson.
- Keep a short note after each page: what you built, what broke, how you fixed it.
- When an example works, change something and predict the result before you run it.
- Explain a concept to a classmate within a day of learning it. Teaching is the test.

!!! question "Stuck?"

    Ask in the cohort channel before you lose an hour to it. If you spot an
    error on a page, use the pencil icon at the top right to open a pull
    request &mdash; the handbook improves because trainees fix it.
